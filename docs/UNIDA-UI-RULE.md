# UNIDA UI DESIGN RULE — 最高优先级（v1.3）

> 本文件是本项目所有 UI 工作的唯一最高约束。任何页面/组件实现前必须先读本文件。
> 来源：用户定稿的品牌规则 + Anthropic frontend-design skill（anthropics/skills）核心原则。

## 0. 身份宣言

你不是在"设计一个类似 UNIDA 的页面"，你是在**实现已经确定的 UNIDA 品牌视觉**。
严禁自由发挥新的 UI 风格。参考目标是 `UI设计参考/` 里的 UNIDA 视觉稿。
UNIDA 不是后台管理系统，是一个年轻人的校园社交产品。

## 1. 品牌

- 名称：UNIDA / 中文：有你搭
- Slogan：在校园，找到和你同频的人
- 关键词：年轻 / 时尚 / 动感 / 活力 / 热爱 / 奔放 / 阳光 / 校园 / 轻社交

## 3. 核心视觉语言

1. 大面积紫色渐变背景（radial 高光 + 135deg 线性渐变）
2. 明亮、轻快、年轻
3. 登录页主视觉以用户定稿插画为唯一来源；次级场景使用简洁几何人物（见第 6 节人物系统）
4. 大圆形装饰（半出血：负 left/right 值）
5. 星星/闪光装饰（✦ + floatStar 浮动动画）
6. 大面积留白
7. 大圆角白色内容层（顶部圆角 42rpx 上移遮罩）
8. 强品牌 Logo（登录页已并入用户定稿图；次级场景可复用品牌紫 U 元素）
9. 单一核心 CTA
10. 不使用传统企业后台风格

## 4. 禁止清单（违反=返工）

- 默认 Dashboard / SaaS UI / 企业后台风格
- 三列卡片堆叠、每个模块都套一个 Card
- 大量边框、大量灰色
- 默认 Tailwind 风格、默认 AI 生成 UI
- 过度信息密度、无意义的渐变卡片
- 自己重新设计品牌（改 logo、改色、改 slogan）
- 正式版使用 emoji 表情（人物必须用 CSS 几何绘制）

## 5. 优先级排序

视觉冲击力 > 信息密度
品牌识别 > 功能堆砌
情绪 > 装饰
留白 > 填满
层次 > 边框

## 6. UNIDA Campus Character System（品牌人物资产）

> 【2026-11-18 用户最终定稿｜V7，覆盖此前 V1–V6】用户已亲自绘制完整登录页设计图 `H:\UniDA\PNG\登录页.png`，项目内原图为 `static/login-design.png`（941×1672）。此图是登录页**唯一视觉内容来源**：U 标志、UNIDA、有你搭、行书标题、副标题、三个人物、校园草坪背景均已画在图内。
> **严禁再叠加任何 AI 背景图、标题图、Logo 图、闪光图或 JS 动态定位。** 此前所有生成图（`login-bg.png` / `login-hero-final.png` / `brand-lockup.png` / `title-*.png` / `logo-mark.png` / `brand-*.png`）全部降级为历史备选，不得再出现在登录页。

**登录页唯一实现方案（V7）**：

- 背景只用一张从用户原图派生的铺屏图 `static/login-design-fill.png`（941×2047）：
  - 顶部补 `140px` 淡紫→浅蓝天空渐变（逐像素融入原图首行），把 Logo 下移，**避开灵动岛/状态栏遮挡**。
  - 底部补 `235px` 草坪渐变（逐像素融入原图末行），**消除下半部分空白**，比例 0.4597 贴近 iPhone Pro 全面屏。
  - 用户原图内容（Logo/文字/人物/草坪）**一个像素都没有改动**。
- 用 `mode="widthFix"` **1:1 完整显示、不裁切**；`.art-wrap` 宽 750rpx，高度由图片比例决定。
- 页面背景用 `linear-gradient(180deg, #d0d1fc 0%, #a9b56d 100%)` 与扩展图上下边缘同色衔接。
- 登录控件 `.dock` 用 `position: fixed`，`left/right: 48rpx`，`bottom: calc(24rpx + env(safe-area-inset-bottom))`（带 `24rpx` 回退），始终贴在屏幕底部安全区之上。
- **登录框完全透明**：`background: transparent`、`border: none`、`box-shadow: none`、`backdrop-filter: none`；删除 `.dock-shine` 高光线，不再有任何框/毛玻璃/投影。
- 只保留三个控件：微信一键登录（微信绿渐变按钮 + CSS 双气泡图标 + 扫光动画 `shineSweep`）、游客先逛逛、协议勾选。
- 透明背景上的文字用白字 + 深紫/深色 `text-shadow` 保证可读；协议链接用品牌黄 `#ffd76a`。
- 禁止：四分类、仅限校园提示、手机号登录、下面再加一个框、任何 emoji、任何“AI生成”字样。

**历史教训（保留供复盘，不可再用于登录页）**：

- 上半插画 + 下半白卡片 = 割裂（用户否决）。
- `aspectFill` 背景 + 固定 `bottom%` 或 JS 反推卡位 = 随屏幕比例漂移。
- 自带玻璃卡 + 插画自带卡 = 双框错位。
- 磨砂玻璃登录框 = 用户明确否决“不要磨玻璃，直接透明”。
- 镜像扩展图片顶部 = 出现倒置 Logo；必须逐像素渐变融合干净天空/草坪区域。
- 唯一稳定解：用户定稿整图 + 无改动扩边 + `widthFix` 1:1 + 完全透明控件。

**技术约定**：

- “动态”仍由 CSS 动效实现：登录页仅保留按钮扫光 `shineSweep`，静态图本身不动。
- `env(safe-area-inset-bottom)` 需带普通 `bottom: 24rpx` 回退，避免旧WebView不支持时控件丢失定位。
- 用户设计图内文字已定稿，禁止再用 PIL 渲染标题图覆盖。

全站次级人物来源（纯 CSS 几何绘制，零 emoji），组件：`components/unida-character/unida-character.vue`。**仅用于空状态、加载、勋章等次要场景；登录页主视觉不得使用。**

| 人物 | body 色 | 系 | 应用场景 |
|---|---|---|---|
| 小 U | 紫 `#7B61FF` | 社交/学习 | 社区、学习场景 |
| 小 N | 黄 `#FFD76A` | 运动/活力 | 运动、组局、 Banner |
| 小 I | 绿 `#34D399` | 娱乐/生活 | 娱乐、空状态 |

（用户定稿登录页插画中的橙 `#FF8A3D`/黄/绿组合，属品牌色板内）

- 结构：白色圆头 + CSS 表情（眼/嘴/腮红/墨镜/菱形星星眼）+ 圆角身体色块
- 复用范围：首页 Banner、空状态、活动完成、积分升级、勋章、加载动画
- 新场景需要人物时，只能复用该组件的 mood/body 变体，禁止另画

## 7. 强制工作流程（一次一个页面）

1. 分析参考截图
2. 建立该页面 Design Token
3. 实现页面
4. 在真实微信小程序环境运行
5. 截图
6. 与参考图视觉比较（Logo 位置 / 标题 / 元素大小 / 比例 / 留白 / 圆角 / 渐变 / CTA / 人物 / 字层级 / 安全区域）
7. 自己指出至少 5 个视觉差异
8. 修改
9. 重新截图
**未达参考图视觉质量，不得进入下一页面。**

页面顺序：登录页 → 首页 → 发现 → 活动详情 → 其余铺开。

## 8. 缺素材原则

不因"没有图片素材"而降级成普通卡片 UI。优先用 CSS 几何图形、渐变、CSS 人物、本地占位素材保持视觉结构。

## 9. 借鉴自 Anthropic frontend-design skill 的通用纪律

- 写码前先明确本页的美学方向（本项目的方向=「活力紫 · 轻社交」，已定，不再另起）
- 每屏至少一个"24 小时后还记得"的记忆点（如登录页的人物+浮动星星）
- 动效服务于情绪：少量高影响（页面入场、星星浮动、按钮反馈）优于满屏微交互
- 留白与层次靠阴影/色块实现，不靠边框
- 注意：skill 提到"紫渐变是 AI 俗套"——UNIDA 的紫是**用户定稿的品牌资产**，必须坚持；要避免的是"随手加的紫色装饰"，不是品牌紫本身
